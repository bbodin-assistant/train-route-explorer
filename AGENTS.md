# Agent Guide

## Project map

- This is a browser-only Rust/WebAssembly application. There is no Node package setup and no Python module.
- Edit browser source files in `www/`. Do not edit `dist/` or `pkg/`; both are generated by `make build`.
- The route timeline and date behavior are implemented in `www/app.js`.
- Timeline and control styling are in `www/style.css`.
- The time controls are declared in `www/index.html`.
- The end-to-end browser smoke test is `tests/ui.test.mjs`.
- `www/data/gtfs.zip` is the local browser-test fixture when present. It is intentionally ignored by Git.

## Timeline and date behavior

- `renderTimeline()` in `www/app.js` owns both the two-hour labels and their vertical guides. They must be generated from the same `ticks` array so they cannot drift apart.
- Timeline dimensions use `--timeline-label-width` and `--timeline-lane-min-width` in `www/style.css`. Use these shared variables for the scale, rows, and guide overlay, including mobile layouts.
- The **Today** button is `#today-button`. It must use the browser's local calendar date, convert it to GTFS `YYYYMMDD` format, and follow the same route-loading path as a manual date change.
- A date may only be selected when it occurs in `state.availableDays`. If today is unavailable, keep the existing selected date and show an error instead of displaying a date for which routes cannot be calculated.
- Date and Today controls remain disabled until a GTFS context is ready and while the app is busy.

## Unrestricted transfer routing

- An empty `connection_stations` list means transfers may occur at any station. It must not mean that transfers are disabled.
- Do not eagerly call `find_trip_segments()` for every station-to-station pair. On the current fixture that expands 49,042 trips and 426,720 stop-time rows into about 2.25 million pairs, with much worse memory growth when path details are cloned.
- The unrestricted path stores trip timetables in `RouteContext.unrestricted_transfer_data` as a compact byte buffer and creates first, middle, and final transfer legs lazily from `UnrestrictedTransferIndex` for the selected service day and transfer-time window.
- `www/worker.js` uses a versioned context-cache key. Increment `CACHE_VERSION` whenever the serialized `RouteContext` representation changes.
- The ignored `benchmark_filtered_and_unrestricted_transfers` Rust test compares filtered and unrestricted routing with `www/data/gtfs.zip`. Run it in release mode:

```bash
cargo test --release benchmark_filtered_and_unrestricted_transfers -- --ignored --nocapture
```

- Also measure the generated WebAssembly when changing this path. Native timings omit the cost of converting the cached context between Wasm and JavaScript.

## Fast validation sequence

Run inexpensive checks first:

```bash
node --check www/app.js
node --check tests/ui.test.mjs
cargo test
git diff --check
```

The `wasm-pack` executable is installed at `/home/toky/.cargo/bin/wasm-pack`, but `/home/toky/.cargo/bin` may not be on `PATH`. Build with:

```bash
env PATH=/home/toky/.cargo/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin make build
```

`wasm-pack` writes to Cargo and wasm-bindgen caches outside the repository. In a restricted agent sandbox, request the required escalation immediately if the build reports a read-only Cargo cache or inability to create a wasm-bindgen temporary directory. Repeating the same sandboxed build will not help.

## Browser smoke test constraints

- `make run` invokes bare `python3`, but this repository has no Python module or PyCharm interpreter configuration. Agents subject to Python-environment rules should use a non-Python static server rather than spending time trying to configure a project interpreter solely to serve `dist/`.
- The available browser executable may be `google-chrome` even though the Makefile defaults to `chromium`. Check once, then run the test with:

```bash
CHROME=google-chrome node tests/ui.test.mjs
```

- Localhost listeners and Chrome's DevTools debugging port may require sandbox escalation. Request it on the first permission-related failure.
- The current 4.7 MB `www/data/gtfs.zip` fixture can take longer than the smoke test's 120-second GTFS-context timeout in constrained environments. A timeout at `GTFS context to be ready`, with no on-page worker error, is an environment/performance limitation and should not trigger repeated identical two-minute reruns.
- Use the full browser test once after the fast checks. If it times out during GTFS parsing, report that limitation and rely on the successful build, syntax checks, Rust tests, IDE inspections, and targeted DOM/CSS assertions. Do not claim the browser smoke test passed.

## Testing expectations for timeline changes

- Keep a browser assertion that the Today button exists beside the date input.
- For guide alignment, compare each time label and guide using `getBoundingClientRect().left`; matching inline percentages alone does not detect mismatched scale and lane widths.
- Improve smoke-test waits by surfacing the page's error status immediately. This distinguishes a real worker failure from slow GTFS processing.
